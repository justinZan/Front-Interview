## 学习方法

每个主题都按以下顺序学习：

1. **读**：先看该章的概念和官方资料；用自己的话写下“它解决什么问题”。
2. **做**：完成该章练习，在项目中制造至少一个异常场景（如网络慢、断线、空数据）。
3. **讲**：不看文档，用 2 分钟回答一个题目；再按文档检查遗漏。
4. **记**：记录代码、截图、测试数据和技术取舍，最后写进项目 README。

## 20 天学习计划

适合每天投入约 1–2 小时。若已熟悉某部分，可跳过基础练习，把时间放在实时数据、图表和项目表达上。周末用于补缺与复盘。

**开始前半天**：先读第 1 章的 HTML/CSS 与浏览器基础，完成语义化筛选表单和响应式卡片布局练习；重点检查键盘操作、Grid/Flex、盒模型、渲染路径与 CORS。

## 时间紧时的优先级

**先掌握**：Vue 3 响应式与组件通信、TypeScript 业务类型、Pinia 状态边界、路由/按钮权限、复杂表格请求、WebSocket/SSE 断线恢复、ECharts 生命周期。

**接着掌握**：首屏与大列表性能、屏幕适配、接口联调和部署、项目结果表达。

**有时间再深挖**：拓扑编辑器选型、多标签页连接共享、Web Worker、完整监控与告警体系。

## 学完的标准

- 能展示一个“设备管理 + 实时监控 + 告警”的项目，并解释数据流。
- 能现场说明断线重连、去重、补拉和图表更新的实现。
- 能解释菜单/按钮权限、服务端鉴权、数据范围之间的关系。
- 能提供至少一次真实测量的性能记录或明确的排查过程。
- 能讲清自己做了什么、为什么这样做、遇到什么问题、结果如何。
