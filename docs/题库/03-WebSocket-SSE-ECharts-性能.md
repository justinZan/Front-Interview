# 面试题库 03｜实时数据、ECharts 与性能

面向设备监控、储能/能源看板、告警推送和企业级大屏。这里以**面试表达**为主；配套原理和代码见 [实时数据与可视化](../03-实时数据与可视化.md)、[性能、交付与项目表达](../04-性能交付与项目表达.md)。

**使用方式**：先遮住“答题要点”口述 60–90 秒，再检查是否交代了问题、方案、边界和验证方法。P0 是岗位直接相关的必会题；P1 是常见深挖题。

## 知识点地图

| 方向 | 必须掌握的关键词 | 能展示的证据 |
|---|---|---|
| 实时连接 | WS/SSE、连接状态机、鉴权、心跳、重连、订阅清理 | 断网恢复录屏、连接日志 |
| 数据一致性 | 快照、增量、游标、序号、去重、乱序、时间戳 | 重复/乱序/缺口模拟结果 |
| ECharts | init/setOption/resize/dispose、数据映射、更新策略 | 实时曲线与容器显隐演示 |
| 能源可视化 | 节点/边/实时值、单位与空值、图表联动 | 简化拓扑或能量流图 |
| 性能 | LCP/INP/CLS、首屏、虚拟滚动、降频、内存 | 相同条件的前后测量记录 |

## A. WebSocket、SSE 与实时状态（Q01–Q15）

### Q01 [P0] 监控台只需接收设备状态，WebSocket 与 SSE 如何选？

- **知识点**：通信方向、协议能力、部署与鉴权。
- **答题要点**：SSE 适合服务器持续单向推送，浏览器原生 `EventSource` 会自动尝试重连；WebSocket 适合在同一连接内双向交换消息。还要比较已有后端网关、代理超时、认证方式、消息频率和断线补偿能力，不能仅凭“实时”二字选 WebSocket。
- **追问**：如果用户需要“确认告警”，是否必须选 WebSocket？不一定；确认可以走普通 HTTP 请求，推送仍用 SSE。

### Q02 [P0] 你会如何定义 WebSocket 连接状态？

- **知识点**：连接生命周期、UI 状态与清理。
- **答题要点**：至少区分未连接、连接中、已连接、重连中、主动关闭；网络失败和用户主动退出应走不同逻辑。状态应映射到界面，如“最后更新于…”和“数据可能过期”，不能断线后继续展示为实时。
- **追问**：页面离开、用户退出、切换站点时各需清理什么？

### Q03 [P0] 断线重连为什么使用指数退避和抖动？

- **知识点**：重连风暴、退避上限、异常分类。
- **答题要点**：固定间隔会使大量客户端在服务恢复时同时重连；指数退避降低压力，随机抖动分散峰值。应设最大间隔，并对主动登出、明确鉴权失败、网络离线等情况区别处理；重连成功后恢复订阅并补数据。
- **追问**：如果重连 10 分钟仍失败，界面如何提示和人工重试？

### Q04 [P0] `error` 和 `close` 事件都触发时，如何避免重复重连？

- **知识点**：单一重连调度器、定时器清理。
- **答题要点**：把重连安排集中在一个状态转换入口，通常让 `close` 负责调度，`error` 只记录诊断信息。保存当前连接实例和定时器句柄；新旧连接事件要比较实例身份，过期事件不改变当前状态。
- **追问**：快速切换站点后，旧连接的 `onmessage` 仍到达该怎么办？

### Q05 [P0] 断线后如何保证设备状态正确？

- **知识点**：快照、增量、游标、补拉。
- **答题要点**：服务端提供带序号的权威快照与可重放增量。前端建立订阅并暂存事件，获取快照后丢弃旧序号并按序应用新事件；检测缺口则补拉或重取快照。只重新连上推送无法恢复断线期间的数据。
- **追问**：快照请求与订阅建立之间有空窗，怎样避免丢事件？

### Q06 [P0] 重复消息和乱序消息怎么处理？

- **知识点**：事件 ID、版本、序号作用域。
- **答题要点**：先明确序号是全站点、每设备还是每主题递增，再按相同作用域比较；事件 ID 去重，设备状态只接受比当前版本新的事件。告警可能经历触发、确认、恢复，不能简单按到达时间覆盖。
- **追问**：设备时间不准时，能否仅凭 `occurredAt` 判新旧？

### Q07 [P0] 实时告警怎样防止重复弹窗？

- **知识点**：告警状态机、幂等、用户通知。
- **答题要点**：按告警 ID 与版本维护状态，重复事件只更新或忽略；恢复事件应关闭/改变相应活跃告警，而不是再创建一条新告警。弹窗通知可另设节流和聚合，但后台状态不能因节流而丢失。
- **追问**：一个站点 1 秒内上百条告警，界面如何展示而不打断用户操作？

### Q08 [P0] 什么是心跳？浏览器端怎样判断连接“假在线”？

- **知识点**：应用层心跳、超时、最后消息时间。
- **答题要点**：连接处于 `OPEN` 只表示浏览器对象的状态，不保证业务消息持续有效。按协议发送/接收应用层心跳或检查服务端定期事件，超时后关闭旧连接并进入重连；阈值需结合正常消息间隔和网络波动。浏览器原生 WebSocket API 不能直接发送协议级 ping 帧，通常要用应用消息。
- **追问**：心跳与业务数据都停止时，怎样避免误报设备离线？

### Q09 [P1] WebSocket 鉴权有哪些常见方案和风险？

- **知识点**：握手、Cookie、短期票据、凭证暴露。
- **答题要点**：浏览器原生 WebSocket 不能像 `fetch` 那样设置任意请求头；常见方案有同源 Cookie、短期一次性票据或建立连接后按协议认证。选择需与后端协调 CSRF/跨站连接、过期、重连和登出清理；避免在 URL 放长期有效令牌。
- **追问**：令牌过期导致所有客户端同时重连，会发生什么？

### Q10 [P1] SSE 的 `id` / `Last-Event-ID` 能保证不丢消息吗？

- **知识点**：SSE 重连游标、服务端事件保留。
- **答题要点**：SSE 事件可带 `id`，浏览器重连时可向服务端表达最后事件 ID，但服务端必须保留并正确重放缺失事件。事件过期、服务端切换或过滤范围改变时仍需快照/补拉策略；不能把浏览器自动重连等同于业务一致性。
- **追问**：如果告警权限在断线期间变化，如何处理补发范围？

### Q11 [P1] 原生 `EventSource` 如何携带认证信息？

- **知识点**：请求头限制、Cookie、CORS 凭证。
- **答题要点**：原生 `EventSource` 不提供任意请求头选项；可在同源场景使用 Cookie，并和后端协商跨源凭证策略。若必须使用自定义 Authorization 头，需考虑基于 `fetch` 的流式实现或调整网关方案，同时实现连接解析与重试。
- **追问**：跨源且需要 Cookie 时，服务端 CORS 响应有什么要求？

### Q12 [P1] 如果实时消息到达速度超过浏览器处理速度怎么办？

- **知识点**：背压、队列上限、合并与丢弃策略。
- **答题要点**：监控消息处理耗时、队列长度与渲染频率；同一设备的“最新值”可覆盖旧值，趋势数据可按时间窗口批量处理，但告警不应随意丢弃。为队列设置上限和过载状态，必要时由服务端聚合或限流。原生 WebSocket 不提供接收背压，需在应用层设计处理策略。
- **追问**：浏览器卡住 5 秒后队列积压 5 万条，你会优先保留哪些数据？

### Q13 [P1] 多个页面都需要设备推送，怎样避免多条重复连接？

- **知识点**：连接所有权、订阅管理、引用计数。
- **答题要点**：在应用服务层持有一条连接，组件按主题注册/取消回调；最后一个订阅者退出时决定是否关闭。用户切换、站点切换和权限变化时重建订阅；不要让组件卸载后留下回调。
- **追问**：多个浏览器标签页能否共享连接？可考虑 SharedWorker/BroadcastChannel 等，但要衡量兼容和复杂度。

### Q14 [P1] 实时消息协议升级后，旧前端如何避免白屏？

- **知识点**：协议版本、运行时校验、兼容转换。
- **答题要点**：消息包含版本或类型标识，接收端先校验字段，再转换为内部模型；无法识别的事件记录并跳过，不能让一个坏消息中断整个连接。版本迁移期间明确兼容窗口，并监控解析失败比例。
- **追问**：TypeScript 类型为何不能替代运行时 JSON 校验？

### Q15 [P1] 设备时间、平台时间和浏览器时间各有什么用途？

- **知识点**：时钟漂移、时间窗口、业务排序。
- **答题要点**：设备发生时间表示测量时点，平台接收时间用于排查传输延迟，浏览器接收时间用于界面诊断。若设备时钟可能漂移，不能仅用它给事件排序或判断新旧；应使用服务端确定的版本/序号，并明确图表横轴使用哪个时间。
- **追问**：从国外站点访问时，历史曲线与告警时间如何展示时区？

## B. ECharts、能源图与大屏（Q16–Q29）

### Q16 [P0] Vue 组件里 ECharts 的完整生命周期是什么？

- **知识点**：容器尺寸、实例、更新、清理。
- **答题要点**：容器实际有宽高后 `init`；数据更新时对现有实例 `setOption`；容器尺寸变更时 `resize`；组件卸载前断开观察器并 `dispose`。隐藏面板重新显示时要检查容器尺寸，不能只依赖 `window.resize`。
- **追问**：`v-if` 与 `v-show` 对图表实例生命周期有何不同？

### Q17 [P0] 图表在弹窗第一次打开时空白，可能是什么原因？

- **知识点**：隐藏容器的 0 尺寸、渲染时机。
- **答题要点**：先看控制台和容器 `clientWidth/clientHeight`；若初始化时弹窗未完成布局，图表会按 0 尺寸渲染。等弹窗显示并完成布局后初始化或调用 `resize`，同时确认数据与 DOM 节点仍对应同一实例。
- **追问**：弹窗关闭后重新打开，你会复用实例还是销毁重建？依据组件是否真正卸载决定。

### Q18 [P0] 实时曲线为什么越运行越卡？

- **知识点**：无限数据、频繁绘制、内存泄漏。
- **答题要点**：检查点数是否无限增长、`setOption` 调用频率、动画/标签成本和是否重复创建实例。限制时间窗口和最大点数，批量更新，必要时采样或服务端聚合；用 Performance 和内存快照验证改善。
- **追问**：降频展示是否允许丢掉告警事件？

### Q19 [P0] 曲线的 0、`null` 和缺失点有什么差别？

- **知识点**：数据语义、图表断点、单位。
- **答题要点**：0 是有效测量值，`null` 常表示该时刻无有效值，缺失点表示事件根本未到或未采集。应与业务方确认断线期间是断开曲线、补 0 还是插值；能源曲线若把无数据画成 0，可能造成错误的业务判断。
- **追问**：功率 kW 与电量 kWh 混在一张图时要注意什么？

### Q20 [P0] `setOption` 默认合并时出现“旧系列残留”怎么处理？

- **知识点**：option 合并、series 身份、替换策略。
- **答题要点**：先检查系列 `id`/`name` 是否稳定；当系列数减少或结构变化较大时，默认合并可能保留旧配置。可按场景使用 `replaceMerge` 替换特定组件，或明确地重建 option；避免每次都重新 `init` 图表。
- **追问**：替换整个 option 会失去哪些交互状态，例如缩放位置？

### Q21 [P1] 图表中如何做站点筛选联动？

- **知识点**：图表事件、业务状态、取消订阅。
- **答题要点**：图表组件把点击事件转换为站点 ID 事件，页面更新统一筛选状态，再驱动其他卡片/列表请求；图表不直接操作其他组件内部状态。绑定的事件监听需随实例销毁解除，避免重复触发。
- **追问**：快速连续点击两个站点，如何处理旧请求覆盖新结果？

### Q22 [P1] 同一页面 20 张小图，Canvas 与 SVG 如何选择？

- **知识点**：渲染器取舍、图元数量、内存。
- **答题要点**：Canvas 常适合图元多、频繁更新的图；SVG 在大量小型图表或需要 DOM 特性时可能有优势。ECharts 官方建议基于真实图表数量、数据点数和目标设备测量，而不是固定选一个渲染器。
- **追问**：如何设计可重复的对比测量？

### Q23 [P1] 图表横轴时间为什么会错 8 小时？

- **知识点**：ISO 8601、UTC、时区解析。
- **答题要点**：先检查服务端时间字符串是否包含时区、时间戳是秒还是毫秒，以及展示时区设置。统一在接口边界解析明确时区的数据，展示时按用户/业务要求转换；不要在组件里手动加减 8 小时。
- **追问**：跨夏令时的历史曲线怎样保持排序正确？

### Q24 [P1] 如何处理高频图表数据：抽样、聚合、限制窗口各解决什么？

- **知识点**：数据量、信息保留、渲染频率。
- **答题要点**：限制窗口控制内存和显示范围；抽样减少图元数，但可能漏掉峰值；聚合按时间桶求均值/最大值等，适合长时间范围。选法要依据监控目的：告警尖峰可能要求保留极值，不能只取均值。
- **追问**：30 分钟窗口和 24 小时窗口能否使用同一粒度？

### Q25 [P1] 能量流图的节点、连线、实时状态为什么要分层建模？

- **知识点**：结构与运行态分离、局部更新。
- **答题要点**：节点/连线表示设备关系，位置表示布局，实时测点表示运行状态；后者高频更新但拓扑结构少变。分层后可只更新受影响节点与边，避免每条消息重建整张图，也方便维护布局版本。
- **追问**：某设备被删除或迁移站点时，哪些层需要更新？

### Q26 [P1] 能源流向有正反方向，如何避免画反？

- **知识点**：业务正方向、符号约定、单位。
- **答题要点**：先和业务方定义每条边的正方向、功率正负号、逆变/充放电含义与单位；把服务端原始值转换成统一的内部模型，再决定动画方向、颜色和文案。应有 0、负值、缺失值、方向切换的样例。
- **追问**：值在 0 附近抖动时，箭头频繁反转怎么办？

### Q27 [P1] 站点拓扑用 ECharts `graph` 还是画布编辑库？

- **知识点**：展示与编辑需求、节点数、交互。
- **答题要点**：先列需求：只展示关系与状态，还是要拖拽、连线编辑、保存版本、吸附与撤销。ECharts `graph` 可快速实现展示型拓扑；复杂组态编辑需评估专门的画布/流程图方案。用一个包含真实节点数与交互的原型验证。
- **追问**：为什么不能只比较库的星数或截图效果？

### Q28 [P0] 大屏在 1920×1080 正常、4K 却变小或模糊，怎么处理？

- **知识点**：CSS 像素、设备像素比、缩放策略。
- **答题要点**：先确认浏览器缩放、系统缩放和设计基准尺寸；选择响应式栅格或受控比例缩放，并为文字/交互设置最小可读尺寸。图表根据容器重新 `resize`，还应在真实目标屏幕验证清晰度和性能。
- **追问**：`transform: scale()` 后鼠标点击和布局占位会出现什么问题？

### Q29 [P1] 监控大屏如何体现数据“新鲜度”？

- **知识点**：最后更新时间、连接与设备状态分离。
- **答题要点**：显示数据采集时间或平台更新时间，并区分“设备离线”和“前端推送断开”。连接中断时可保留旧数据，但标注可能过期；超过业务阈值可改变状态样式或要求手动刷新。
- **追问**：设备未上报但连接正常，界面应显示什么？

## C. 首屏、大列表与运行时性能（Q30–Q42）

### Q30 [P0] 面试官说“页面卡”，你怎样先定位？

- **知识点**：场景、基线、Network/Performance。
- **答题要点**：先问卡在首次打开、点击、滚动还是运行一段时间后，固定设备、数据量和网络重现。Network 看请求瀑布和资源大小；Performance 看主线程脚本、布局与绘制；内存面板排查持续增长。选一项主因改动，再在同条件下复测。
- **追问**：你会记录哪些数值，如何证明优化有效？

### Q31 [P0] LCP、INP、CLS 分别代表什么？

- **知识点**：加载、交互、稳定性指标。
- **答题要点**：LCP 关注主要内容出现的时间，INP 关注用户交互后的响应，CLS 关注意外布局移动。它们从不同角度描述体验；实验室分数和真实用户数据可能不同，应与具体业务场景一起看。
- **追问**：接口很快，LCP 仍很差，可能在哪里耗时？

### Q32 [P0] 首屏慢时，你会怎样按优先级处理？

- **知识点**：关键路径、代码拆分、缓存与资源。
- **答题要点**：先确认慢在服务器响应、资源传输、JS 执行还是渲染；再减少首屏必须下载和执行的代码，按路由懒加载图表等重依赖，优化图片/字体并利用合适缓存。骨架屏改善等待感受，不能替代实际加载优化。
- **追问**：图表组件已经动态 import，为什么首页仍加载 ECharts？

### Q33 [P0] 10 万台设备的表格为什么优先考虑服务端分页？

- **知识点**：网络量、内存、DOM 成本、查询能力。
- **答题要点**：服务端分页和筛选可使浏览器只持有当前需要的数据，降低传输、解析和内存压力；虚拟滚动主要减少同时存在的 DOM 节点，不会自动减少已下载的数据。要先看产品是否真需连续浏览全部设备，再决定是否叠加虚拟列表。
- **追问**：服务端分页下怎样保证排序与总数一致？

### Q34 [P0] 虚拟滚动的基本计算是什么？

- **知识点**：可视范围、起始索引、占位高度、缓冲区。
- **答题要点**：定高列表可用 `scrollTop / rowHeight` 计算起始索引，按容器高度算可见行数，并在前后加 overscan；用占位元素维持总滚动高度，仅渲染窗口内行。动态行高、固定列、键盘焦点和滚动定位会使实现复杂化。
- **追问**：为什么虚拟列表快速滚动时会出现白屏或跳动？

### Q35 [P1] 行高不固定时，虚拟滚动会遇到什么困难？

- **知识点**：高度估算、测量、位置修正。
- **答题要点**：无法简单用索引乘固定高度得到位置；需要估算、测量实际行高并维护累计高度，同时避免修正造成滚动跳动。若数据量不极端或内容可折叠，分页可能比自研动态高度虚拟列表更稳妥。
- **追问**：展开详情后滚动位置如何保持？

### Q36 [P1] 路由懒加载会带来哪些新问题？

- **知识点**：chunk 请求、失败处理、访问路径。
- **答题要点**：懒加载减少首屏资源，但首次进入该路由会有额外网络请求；过度拆分会产生很多小 chunk。发布时旧页面引用已删除 chunk 可能加载失败，需要合理缓存和发布策略，并为加载失败提供可恢复的体验。
- **追问**：如何确定某个依赖应放公共包还是路由包？

### Q37 [P1] 实时更新导致 Vue 组件频繁重渲染，怎么定位？

- **知识点**：响应式边界、组件更新、批量处理。
- **答题要点**：用 Vue Devtools/Performance 找到高频更新组件，检查是否把整个设备集合替换、或把无关状态放在共享父组件。按设备 ID 局部更新，拆出稳定子组件，批量写入最新值；对于大型不可变数据可考虑 `shallowRef` 并整体替换。
- **追问**：把所有实时数据放 Pinia 会自动变快吗？

### Q38 [P1] 为什么页面运行 8 小时后才变慢？

- **知识点**：累积型资源问题。
- **答题要点**：检查图表点数、队列长度、定时器、事件监听、WebSocket 连接和 ECharts 实例是否持续增长。比较刚打开与长时间运行的内存和 CPU，反复进入/离开页面观察资源数量；修复后同样长时间验证。
- **追问**：如何用浏览器内存快照找仍被持有的组件对象？

### Q39 [P1] `ResizeObserver` 回调里直接重绘所有图表有何问题？

- **知识点**：布局反馈循环、频繁 resize。
- **答题要点**：容器尺寸可能在一次布局变化中多次通知，全部重绘会带来额外开销；如果回调又改变容器尺寸，可能形成反馈。应只处理相关图表、检查尺寸确实变化，并按需调度到下一帧；组件卸载时断开观察器。
- **追问**：侧栏动画持续 300 ms 时，图表 resize 频率如何控制？

### Q40 [P1] Web Worker 适合解决哪类监控台性能问题？

- **知识点**：主线程、可迁移计算、通信成本。
- **答题要点**：大量数据解析、聚合或采样等纯计算可移到 Worker，减少主线程阻塞；DOM 和一般图表实例操作仍需在主线程或专门支持的渲染方案中完成。跨线程传输也有成本，先量化计算耗时再决定是否使用。
- **追问**：每条小消息都发给 Worker 可能有什么问题？

### Q41 [P1] 如何设置前端性能监控而不产生噪声？

- **知识点**：真实用户指标、版本、采样、隐私。
- **答题要点**：收集关键页面的 LCP/INP/CLS、JS 错误、接口耗时和页面版本，并区分设备与网络条件；按业务重要性采样与告警。对敏感数据脱敏、控制日志量，发现异常后能关联到具体发布版本和用户操作路径。
- **追问**：为什么不能只看平均值？

### Q42 [P1] 如何证明“优化后更快”而非测试条件变化？

- **知识点**：可重复测量、基线、分位数。
- **答题要点**：固定构建版本、数据量、浏览器、设备、网络和缓存状态，重复多次比较中位数或分位数；同时检查错误率和内存。记录优化前后关键路径与改动，不用单次截图或体感宣称提升。
- **追问**：实验室快了但真实用户没改善，你下一步看什么？

## 练习顺序与自测

1. **第一轮（P0）**：先练 Q01–Q08、Q16–Q20、Q28、Q30–Q34。每题限时 90 秒，必须说出业务场景与一个边界。
2. **第二轮（P1）**：用追问继续深挖；每答不出一题，就在练习项目制造相应异常并记录处理过程。
3. **第三轮（设计题）**：选 Q05、Q12、Q25、Q33 画出数据流或组件结构，说明替代方案和取舍。
