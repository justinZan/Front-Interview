# 题库 01｜HTML、CSS、JavaScript、TypeScript 与浏览器

适用岗位：Vue 3 企业后台、实时监控和能源物联网可视化。**P0** 为核心题，**P1** 为延伸题。

## 知识点地图

| 领域 | 必会知识点 | 在本岗位中的用途 |
|---|---|---|
| HTML | 语义、表单标签、表格、键盘操作 | 设备筛选、告警表格、弹窗 |
| CSS | 盒模型、Flex/Grid、层叠、滚动容器、响应式 | 后台布局、复杂表格、大屏 |
| JavaScript | 作用域、`this`、原型、异步、事件、内存 | 实时连接、请求竞态、交互性能 |
| TypeScript | 联合类型、收窄、泛型、`unknown`、运行时校验 | API 契约、设备状态、消息处理 |
| 浏览器与 HTTP | 渲染、缓存、CORS、安全、请求语义 | 首屏优化、跨域联调、部署排障 |

## A. HTML 与 CSS（01–10）

### 01 [P0] 设备筛选表单为何不能只用 `placeholder` 标注输入框？

- **知识点**：`label`、控件名称、表单可访问性。
- **参考回答**：占位文字在用户输入后消失，也不一定被辅助技术当成可靠标签。应使用与控件关联的 `<label for="...">`，错误提示用文字并通过 `aria-describedby` 关联；组件库最终也应输出合理的原生语义。
- **追问/场景**：多个搜索框只有图标时，如何让键盘和读屏用户区分？

### 02 [P0] “查看详情”应使用按钮还是链接？

- **知识点**：HTML 语义、键盘行为、导航。
- **参考回答**：跳到可分享或可打开新标签的 URL 用链接；执行当前页动作（打开抽屉、提交、确认告警）用按钮。语义元素自带焦点、键盘和浏览器行为，避免用可点击 `div` 重造这些能力。
- **追问/场景**：表格里点击设备名进入独立详情页，同时旁边有“编辑”弹窗，应分别选什么元素？

### 03 [P1] 大表格的表头、表体与状态信息如何组织？

- **知识点**：`table`、`th`、`scope`、表头关系、空状态。
- **参考回答**：真正的二维数据优先使用表格语义，列头用 `th` 并正确声明范围。表格标题、筛选条件、排序状态和空结果提示要让用户能理解当前数据；虚拟化表格若改变 DOM 结构，应检查键盘导航和辅助技术表现。
- **追问/场景**：设备有分组表头和固定列时，如何验证读屏顺序？

### 04 [P1] 弹窗打开和关闭后如何管理键盘焦点？

- **知识点**：焦点陷阱、初始焦点、焦点恢复。
- **参考回答**：打开后焦点应进入弹窗内合理位置，Tab 不应无意跑到背景页面；关闭后焦点返回触发按钮。第三方组件库可能内置部分行为，但仍需检查表单错误定位和异步关闭场景。
- **追问/场景**：用户点“确认告警”后服务端返回字段错误，应将焦点放在哪里？

### 05 [P0] Flex 子项内容过长导致页面横向溢出，如何排查？

- **知识点**：自动最小尺寸、`min-width: 0`、换行与溢出。
- **参考回答**：先用 DevTools 找出实际撑宽的子项，检查长文本、表格、图片和子项默认最小宽度。在需要收缩的 Flex 子项上设置合适的 `min-width: 0`，再决定文本换行、截断或局部滚动；直接给整个页面 `overflow: hidden` 可能掩盖问题。
- **追问/场景**：筛选栏按钮很多时，是压缩按钮还是让它们换行？依据是什么？

### 06 [P0] 监控大屏为什么常用 Grid，`minmax(0, 1fr)` 解决什么？

- **知识点**：二维布局、网格轨道最小尺寸。
- **参考回答**：Grid 适合同时控制多列多行的指标卡与图表区域。`minmax(0, 1fr)` 允许网格轨道收缩到零，避免图表或长文本的最小内容宽度撑破布局；仍需给图表容器明确高度并在尺寸变化时重新计算图表。
- **追问/场景**：1920×1080 和 4K 比例相同，为什么简单放大字号仍可能不合适？

### 07 [P0] `box-sizing: border-box` 是否让 `width: 100%` 一定不溢出？

- **知识点**：盒模型、margin、最小宽度、子元素尺寸。
- **参考回答**：`border-box` 使声明宽度包含 padding 和 border，但 margin 仍在外部；子元素、长单词、表格或 Flex/Grid 的默认最小尺寸也可能造成溢出。应看实际盒尺寸和父容器约束，而非只检查 `width`。
- **追问/场景**：一行两个 `width: 50%` 卡片再加 `gap`，为什么会超出容器？

### 08 [P1] `z-index: 9999` 仍盖不住别的元素，可能是什么原因？

- **知识点**：层叠上下文、定位、裁剪。
- **参考回答**：`z-index` 只在相关层叠上下文内比较；父元素创建了较低的层叠上下文时，子元素数值再大也未必能超过外部层级。还要排查祖先的 `overflow` 裁剪和弹窗挂载位置；可优先使用组件库统一的层级规范或将浮层挂到合适容器。
- **追问/场景**：图表 tooltip 被侧栏挡住，如何定位是哪一层造成的？

### 09 [P1] `position: sticky` 不生效时看哪里？

- **知识点**：滚动容器、粘性定位阈值、布局约束。
- **参考回答**：确认设置了 `top` 等阈值，元素所在滚动容器有足够滚动距离，并检查祖先 `overflow` 与容器高度。后台“固定表头”若表格自身有滚动区域，sticky 应相对实际滚动容器设计。
- **追问/场景**：页面整体滚动与表格内部滚动同时存在，表头应跟随哪一个？

### 10 [P1] BFC 能解决哪些老页面布局问题？

- **知识点**：块级格式化上下文、浮动、margin 折叠。
- **参考回答**：BFC 可容纳内部浮动，并让某些相邻外边距折叠行为与外部隔离。`display: flow-root` 是显式创建 BFC 的方法；现代后台优先用 Flex/Grid 做主要布局，但排查旧页面的浮动和高度塌陷时仍要理解 BFC。
- **追问/场景**：父容器只包含浮动子元素，高度为何看起来为零？

## B. JavaScript（11–25）

### 11 [P0] `||` 与 `??` 在功率值展示上有什么区别？

- **知识点**：假值、空值合并。
- **参考回答**：`0 || '暂无数据'` 会得到“暂无数据”，把真实的 0 kW 错当缺失；`0 ?? '暂无数据'` 保留 0，仅对 `null` 和 `undefined` 使用兜底。业务上还应区分“零值”“测点无效”和“消息未到达”。
- **追问/场景**：接口返回空字符串时，页面应该显示空字符串还是默认文案？谁来决定？

### 12 [P0] 普通函数和箭头函数的 `this` 有何差异？

- **知识点**：调用方式决定 `this`、箭头函数词法 `this`。
- **参考回答**：普通函数的 `this` 由调用方式确定；箭头函数不建立自己的 `this`，使用创建位置的 `this`。把对象方法随意改成箭头函数可能失去预期的对象上下文，事件回调也不能只靠 `this` 猜测当前节点。
- **追问/场景**：将对象方法解构后单独调用，`this` 还指向原对象吗？

### 13 [P1] JS 原型链与 `class` 是什么关系？

- **知识点**：属性查找、原型、继承。
- **参考回答**：对象查找属性时会沿原型链继续查找；`class` 是构造对象和原型方法的一种语法形式，并未改变 JS 基于原型的本质。理解原型有助于解释共享方法、`instanceof` 和意外的继承属性。
- **追问/场景**：用 `for...in` 枚举接口对象时，为什么可能读到原型上的属性？

### 14 [P0] 浅拷贝与深拷贝有什么差别？

- **知识点**：对象引用、嵌套数据、不可变更新。
- **参考回答**：展开运算符只复制第一层属性，嵌套对象仍共享引用；修改嵌套设备配置可能同时影响原状态。深拷贝要考虑 Date、Map、循环引用、函数等数据类型；做状态更新时通常只复制需要改变的路径，并明确数据所有权。
- **追问/场景**：为什么 `const next = {...device}` 后修改 `next.meta.site.name` 仍改变旧值？

### 15 [P0] 如何避免快速切换站点时旧请求覆盖新请求？

- **知识点**：异步竞态、取消、请求序号。
- **参考回答**：每次筛选变化产生新请求，旧请求可能更晚返回。可以用 `AbortController` 取消旧请求，同时用请求序号或当前参数校验避免过期响应更新页面；加载和错误状态也应只由当前请求修改。
- **追问/场景**：请求库无法真正取消时，仍可如何保证 UI 正确？

### 16 [P1] 防抖、节流、批处理各适合什么？

- **知识点**：高频事件调度、延迟与吞吐取舍。
- **参考回答**：防抖适合“停止输入后再搜索”；节流适合需要周期性反馈的滚动或拖动；批处理适合把多条实时消息合成一次状态更新。对告警不能随意丢弃事件，可批量处理但要保持去重和状态顺序。
- **追问/场景**：每秒 100 条设备测点，图表只想每秒刷新 4 次，怎么组织队列？

### 17 [P0] `Promise.all` 和 `Promise.allSettled` 如何选择？

- **知识点**：并发结果、失败语义。
- **参考回答**：多个请求都必需成功才可继续时用 `Promise.all`；一个拒绝会使聚合 Promise 拒绝，但其他请求不会自动取消。允许部分成功且要呈现各项结果时用 `Promise.allSettled`，例如大屏多个互不依赖的卡片接口。
- **追问/场景**：若两个请求有依赖关系，是否应直接并发？

### 18 [P0] `async/await` 中的异常如何传播？

- **知识点**：Promise 拒绝、`try/catch/finally`。
- **参考回答**：`await` 的 Promise 拒绝会在当前位置表现为抛错，可由本层 `try/catch` 捕获，或继续传播给调用方。应决定哪一层负责错误分类、哪一层负责展示消息；`finally` 可清理加载状态，但不能让旧请求错误覆盖新请求状态。
- **追问/场景**：忘记 `await saveDevice()` 后外层 `try/catch` 能否捕获它的异步失败？

### 19 [P0] 事件委托为什么适合动态表格？

- **知识点**：事件冒泡、目标匹配、监听器数量。
- **参考回答**：把监听器放在稳定的表格容器上，通过事件目标识别具体按钮或行，可以避免每次增删行都重新绑定大量原生监听器。需留意不冒泡的事件、嵌套点击目标与权限禁用状态；在 Vue 中普通模板事件通常已由框架管理，不要为了“优化”强行改成原生委托。
- **追问/场景**：点击操作按钮时如何避免同时触发行点击详情？

### 20 [P1] `Map`、普通对象与 `WeakMap` 如何选择？

- **知识点**：键类型、遍历、弱引用。
- **参考回答**：`Map` 可用任意值作键，适合按设备 ID/节点对象存索引；普通对象适合固定结构数据。`WeakMap` 的键必须是对象且不阻止键被垃圾回收，适合给 DOM 或对象附加私有元数据，但不可遍历，不能拿来做需导出的设备清单。
- **追问/场景**：ECharts 实例按 DOM 元素缓存时为何可能考虑 `WeakMap`？

### 21 [P1] ES Module 的导入是值的拷贝吗？

- **知识点**：模块绑定、模块缓存、循环依赖。
- **参考回答**：ES Module 导入的是只读的实时绑定，不是导出时值的独立拷贝；导出方更新绑定后，导入方能看到新值。模块初始化通常只执行一次；循环依赖可能因初始化顺序产生暂时不可用的绑定，应理清依赖方向。
- **追问/场景**：为什么把两个 store 互相静态导入可能产生难排查问题？

### 22 [P0] 下面代码的输出顺序是什么？为什么？

```js
console.log('A')
setTimeout(() => console.log('B'), 0)
Promise.resolve().then(() => console.log('C'))
queueMicrotask(() => console.log('D'))
console.log('E')
```

- **知识点**：调用栈、微任务、定时器任务。
- **参考回答**：通常输出 `A E C D B`。同步语句先运行；已排队的 Promise 回调和 `queueMicrotask` 按入队顺序在下一任务前处理；定时器回调稍后运行。递归不断添加微任务可能阻碍后续任务和渲染。
- **追问/场景**：`setTimeout(fn, 0)` 为什么不是立刻执行？

### 23 [P1] 为什么页面退出后仍可能发生“内存泄漏”？

- **知识点**：可达性、监听器、定时器、闭包、连接。
- **参考回答**：组件虽然卸载，但全局监听器、定时器、WebSocket 订阅或图表实例可能继续持有回调和 DOM 引用，使对象保持可达。要在对应生命周期解除订阅、清理定时器、关闭连接或释放图表；用内存快照和资源数量验证。
- **追问/场景**：路由来回切换 20 次后连接数变成 20，如何定位？

### 24 [P1] `Array.sort()` 为什么容易意外修改状态？

- **知识点**：原地变更、不可变更新、比较函数。
- **参考回答**：`sort()` 原地修改数组，直接对共享状态排序可能影响其他组件的顺序。若需要新顺序可复制后排序或使用新数组 API；比较函数应返回数值并明确空值、时间和数字的规则。
- **追问/场景**：设备列表按“最后上报时间”排序，时间字符串缺时区时有什么风险？

### 25 [P1] `Object.freeze()` 能替代深层不可变约束吗？

- **知识点**：浅冻结、嵌套引用、运行时约束。
- **参考回答**：`Object.freeze()` 默认只冻结对象自身属性，对嵌套对象不会递归生效；TypeScript 的 `readonly` 主要是静态检查，运行时也不能防止外部 JS 代码修改。对 API 数据最好建立清楚的数据所有权，必要时在边界复制或验证。
- **追问/场景**：冻结数组后，其中的设备对象字段还能改吗？

## C. TypeScript（26–34）

### 26 [P0] `unknown` 与 `any` 在解析实时消息时有什么区别？

- **知识点**：不可信数据边界、类型收窄。
- **参考回答**：`any` 会绕过大部分类型检查；`unknown` 要求先验证或收窄才能读取字段。`JSON.parse` 得到的数据应按不可信输入处理，检查事件类型、必需字段、单位和范围，之后再进入业务状态。
- **追问/场景**：服务器突然把 `powerKw` 从数字改成字符串，静态接口类型为何没阻止运行时错误？

### 27 [P0] 为什么设备状态适合用判别联合？

- **知识点**：联合类型、判别字段、穷尽检查。
- **参考回答**：不同状态可要求不同字段，例如在线时有最新测点，离线时有离线时间；以 `status` 作为判别字段，`switch` 后 TypeScript 会收窄具体分支。这样比“所有字段都可选”更能表达业务约束。
- **追问/场景**：新增 `maintenance` 状态后，如何让编译器提示遗漏的展示分支？

### 28 [P0] `never` 有什么实际用途？

- **知识点**：不可能值、穷尽性校验。
- **参考回答**：在完整处理联合类型的分支后，剩余值应为 `never`。把剩余值传给接收 `never` 的函数，新增状态未处理时编译器就能报错，特别适合设备状态和告警事件类型。
- **追问/场景**：接口传来未知状态字符串时，运行时仍要怎样兜底？

### 29 [P0] 泛型比把 API 返回值写成 `any` 好在哪里？

- **知识点**：类型参数、复用、约束。
- **参考回答**：`PageResult<T>` 可以保留 `items` 中的具体设备或告警类型，让列表组件和 API 函数复用同一种分页结构，同时仍有字段检查。必要时用泛型约束保证行对象具有 `id` 等字段；不要为简单固定类型引入过度复杂的泛型。
- **追问/场景**：一个表格组件要求每行都有稳定 `id`，泛型约束怎么写？

### 30 [P1] `Partial<T>` 能直接作为更新接口的请求类型吗？

- **知识点**：映射类型、业务约束、字段白名单。
- **参考回答**：`Partial<T>` 把所有字段变为可选，可能意外允许修改 `id`、服务端生成时间或实时测点。更新请求通常应先 `Pick` 可修改字段，再 `Partial`，并在运行时或服务端校验；类型便利不能代替业务契约。
- **追问/场景**：设备名称可以改、在线状态不能改，如何建模 `PATCH /devices/:id`？

### 31 [P1] `readonly` 是否保证请求数据永远不被修改？

- **知识点**：编译期约束、浅层性、运行时数据。
- **参考回答**：TypeScript 的 `readonly` 主要在编译时约束赋值，不能保证运行时对象被冻结，普通 `readonly` 对嵌套对象也不一定是深只读。外部数据仍需验证，团队应约定谁有权修改状态，并使用明确的更新函数。
- **追问/场景**：`readonly` 数组中的对象属性是否自动只读？

### 32 [P0] 什么时候需要自定义类型守卫？

- **知识点**：控制流收窄、`value is T`、运行时检查。
- **参考回答**：当值来自 WebSocket、URL 参数或第三方库，静态类型未知时，可通过检查字段后用类型守卫缩小类型。类型守卫的实现必须真的检查关键字段；只写 `return true` 或直接断言会掩盖问题。
- **追问/场景**：设备事件 `type: 'metric.reported'` 时如何确保 `payload.powerKw` 是有限数字？

### 33 [P1] 结构类型系统会带来什么意外？

- **知识点**：结构兼容、额外属性检查、领域 ID。
- **参考回答**：TypeScript 通常根据对象形状判断兼容性，而不是类型名字；两个都有 `id: string` 的对象可能被错误混用。对象字面量直接赋值时有额外属性检查，但通过变量传递可能表现不同；重要领域 ID 可用明确包装或品牌类型区分。
- **追问/场景**：如何避免把 `siteId` 误传到需要 `deviceId` 的函数？

### 34 [P1] 可选属性和 `number | null` 是一回事吗？

- **知识点**：缺失、显式空值、API 契约。
- **参考回答**：可选属性表示字段可能不存在；`number | null` 表示字段存在但值可明确为空。监控数据里 `0 kW`、`null`（测点无效）和字段缺失（服务端未返回）可能有不同业务意义，应在类型与展示上区分。
- **追问/场景**：图表中缺失点、零值和断线分别怎样绘制或提示？

## D. 浏览器、HTTP 与安全（35–44）

### 35 [P0] 浏览器从 HTML/CSS 到显示页面经历哪些主要步骤？

- **知识点**：DOM、CSSOM、布局、绘制、合成。
- **参考回答**：浏览器解析 HTML 与 CSS，计算元素样式和布局，再绘制并合成可见内容。JavaScript、样式和资源加载都可能影响关键路径；分析首屏慢时要结合 Network 与 Performance，找出等待、脚本执行或布局哪个占主导。
- **追问/场景**：一个大图表路由首次打开慢，如何区分依赖下载和绘制开销？

### 36 [P1] 强制同步布局是什么？怎样在监控页避免它？

- **知识点**：布局失效、读写交错、主线程。
- **参考回答**：脚本修改样式后立即读取几何尺寸，浏览器可能不得不提前计算布局；在大量节点上反复读写会造成性能问题。可以把测量与写入分批、减少节点、借助 `ResizeObserver` 感知容器变化，并先用 Performance 录制确认瓶颈。
- **追问/场景**：每条实时消息都调用 `getBoundingClientRect()` 再改样式，会有什么影响？

### 37 [P0] `Cache-Control: no-cache` 与 `no-store` 有什么区别？

- **知识点**：缓存存储、再验证。
- **参考回答**：`no-cache` 允许存储响应，但复用前要向服务端验证；`no-store` 要求缓存不要存储该响应。带哈希的静态 JS/CSS 通常可长时间缓存，HTML 常需及时验证新版本；具体策略要结合是否包含个性化数据。
- **追问/场景**：发布后旧 HTML 引用已删除的 chunk 导致白屏，缓存与发布流程该如何调整？

### 38 [P1] `ETag` 与 `304 Not Modified` 怎样配合？

- **知识点**：条件请求、传输优化。
- **参考回答**：服务端给资源版本标识 `ETag`；客户端后续可带 `If-None-Match` 请求。资源未变化时服务端可返回 304，不重传响应体；这仍发生了网络往返，和直接命中新鲜缓存不同。
- **追问/场景**：为什么已经有 ETag，页面加载仍能感觉慢？

### 39 [P0] 跨源请求为什么会先出现 `OPTIONS`？

- **知识点**：CORS 预检、方法与请求头。
- **参考回答**：某些跨源请求在实际请求前需要浏览器预检，询问服务端是否允许该方法和请求头。检查 Network 中预检的 `Origin`、`Access-Control-Request-Method/Headers`，以及响应的允许源、方法和头；开发代理只能改变本地浏览器看到的请求来源，生产仍要正确配置网关。
- **追问/场景**：加了 `Authorization` 请求头后本地请求多了一次 OPTIONS，该谁处理？

### 40 [P0] 带 Cookie 的跨域请求能设置 `Access-Control-Allow-Origin: *` 吗？

- **知识点**：CORS 凭证、允许源、Cookie 策略。
- **参考回答**：带凭证的 CORS 请求不能用通配符允许源，需要服务端返回明确允许的源并启用凭证许可；前端也要按请求库设置携带凭证。即使 CORS 正确，Cookie 的 `SameSite`、`Secure` 等属性还可能阻止跨站发送。
- **追问/场景**：浏览器请求带不上登录 Cookie，要从哪几层排查？

### 41 [P0] CORS 能阻止恶意用户直接调用接口吗？

- **知识点**：浏览器访问控制、服务端鉴权。
- **参考回答**：CORS 限制浏览器脚本读取跨源响应，不是服务端身份或权限校验。攻击者可以通过其他客户端发请求；设备编辑、告警确认等接口必须由服务端验证身份、权限和数据范围。
- **追问/场景**：前端隐藏编辑按钮、CORS 只允许公司域名，接口是否安全？

### 42 [P0] 如何防止设备名称等用户输入导致 XSS？

- **知识点**：输出编码、HTML 注入、可信内容。
- **参考回答**：把设备名称当文本渲染，避免将未经处理的数据直接拼进 `innerHTML` 或 Vue 的 `v-html`。确需渲染富文本时采用有明确规则的净化与内容安全策略，并审查第三方内容；不能只依赖输入端过滤。
- **追问/场景**：后端返回的告警描述含 HTML 标签，页面应该怎样显示？

### 43 [P1] Cookie 会话与 `localStorage` 中的 token 有哪些安全取舍？

- **知识点**：XSS、CSRF、`HttpOnly`、`SameSite`。
- **参考回答**：`HttpOnly` Cookie 不可被页面 JS 读取，可降低脚本直接窃取会话值的风险，但要设计 CSRF 防护并正确配置 `SameSite`、`Secure`。`localStorage` 中的 token 可由同源脚本读取，XSS 风险更直接；它是否适合取决于系统威胁模型与后端认证方案，不能一概而论。
- **追问/场景**：为什么“改成 Cookie”也不能让 XSS 问题消失？

### 44 [P1] 网络失败时能对所有请求自动重试吗？

- **知识点**：幂等性、重复提交、退避。
- **参考回答**：查询请求通常较适合有边界地重试；创建、确认告警、设备控制等操作可能已经在服务端成功，只是响应丢失，直接重试会重复执行。写操作应考虑幂等键、服务端状态查询或明确的重试协议；任何重试都要限制次数和等待时间。
- **追问/场景**：点击“确认告警”后超时，前端如何判断能否安全重试？
