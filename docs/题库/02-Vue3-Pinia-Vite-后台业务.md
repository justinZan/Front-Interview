## A. Vue 3 响应式与渲染（1–10）

### 1. [P0] `ref` 与 `reactive` 有什么区别，设备列表选哪个？

**核心知识点**：引用包装、对象代理、整体替换、模板解包。

**参考答题**：`ref` 用 `.value` 持有任意值，适合基本类型和需要整体替换的列表；`reactive` 直接代理对象，适合按字段修改的结构。列表接口每次返回新数组时，`ref<Device[]>([])` 便于整体赋值；表单对象可用 `reactive`，但要注意普通解构会断开属性与原代理的联系。

**追问**：把 `reactive({ keyword: '' })` 解构成 `const { keyword } = form` 后，为什么模板不更新？怎么用 `toRefs` 处理？

### 2. [P0] 为什么修改响应式数据后，立即读取 DOM 可能还是旧值？

**核心知识点**：批量更新、DOM 更新周期、`nextTick`。

**参考答题**：Vue 会把同一轮的状态修改合并调度，避免每次赋值都重新渲染。状态值通常已变，但 DOM 更新要等渲染队列执行；必须依赖新 DOM 尺寸或节点时，可在 `await nextTick()` 后读取。能用响应式数据直接计算的结果，不应为了读 DOM 而滥用 `nextTick`。

**追问**：图表容器由 `v-if` 显示后，何时调用 ECharts 的 `init` 或 `resize`？

### 3. [P0] `computed`、`watch`、`watchEffect` 分别适合什么？

**核心知识点**：派生状态、副作用、依赖收集。

**参考答题**：`computed` 返回可缓存的派生值，例如“在线设备数”；`watch` 监听明确数据源并执行副作用，例如筛选变化后请求列表；`watchEffect` 自动追踪同步执行时读取的依赖，适合简单副作用。不要用 watcher 把一个字段复制到另一个字段来维护本可计算的结果。

**追问**：`watchEffect(async () => { await ...; console.log(x.value) })` 中，`await` 之后读取的 `x` 一定会被追踪吗？

### 4. [P0] `watch` 请求接口时如何避免旧请求覆盖新结果？

**核心知识点**：清理函数、取消请求、请求序号。

**参考答题**：每次监听回调创建 `AbortController`，在本次回调失效时取消旧请求；请求库不支持取消时，用递增序号或当前查询快照忽略旧响应。同时只让当前请求修改 `loading` 和错误状态，否则旧请求的 `finally` 可能提前关闭新请求的加载提示。

**追问**：用户离开页面时应该清理什么？请求已返回但回调尚未执行时如何判断是否仍有效？

### 5. [P1] 深度监听为什么可能很贵？能否只监听具体字段？

**核心知识点**：嵌套遍历、监听源、精确依赖。

**参考答题**：深度监听需要追踪对象内部变化，数据量大时会增加遍历与触发成本。后台筛选页通常只关心 `keyword`、`status`、`page`，可监听这些 getter/引用组成的数组；对于整个新对象替换，也可改为不可变赋值并只监听引用。选择应根据数据形态和更新频率。

**追问**：图表实时点数组应放进深层响应式对象吗？`shallowRef` 何时有帮助？

### 6. [P0] `v-if` 和 `v-show` 怎么选？

**核心知识点**：创建销毁与显示隐藏、切换频率、资源生命周期。

**参考答题**：`v-if` 根据条件创建或销毁子树，初始为 false 时没有对应 DOM；`v-show` 保留 DOM，只改显示状态。频繁切换且创建成本高的简单区域可用 `v-show`；权限、复杂图表或不会频繁出现的内容要考虑 `v-if` 的资源清理和初始成本。具体还应看图表隐藏后尺寸为 0 的问题。

**追问**：将含 WebSocket 订阅的组件改成 `v-show` 后，为什么隐藏状态仍收消息？

### 7. [P0] `v-for` 为什么需要稳定 `key`？

**核心知识点**：节点复用、组件本地状态、排序与插入。

**参考答题**：`key` 帮助 Vue 在更新时识别同一个业务项。用数组下标作为可排序设备列表的 key，插入或删除行后，组件内部输入值、展开状态等可能被错误复用到另一条数据。优先使用设备 ID 这样稳定且唯一的标识。

**追问**：分页后不同页有相同数组下标，行内编辑组件可能出现什么问题？

### 8. [P1] `KeepAlive` 缓存页面后，数据和订阅如何管理？

**核心知识点**：激活/失活、缓存实例、资源清理。

**参考答题**：缓存页切走时组件未必卸载，`onUnmounted` 不会立即运行；应根据业务使用 `onActivated`、`onDeactivated` 控制刷新、定时器和订阅。筛选状态可保留，但实时连接若由页面独占，失活时是否暂停要明确；若由应用级连接共享，则页面只解除自己的订阅。

**追问**：用户从设备详情返回列表，如何决定是复用缓存还是重新拉取？

### 9. [P1] 为什么不建议在模板中调用昂贵函数计算每一行？

**核心知识点**：渲染重执行、计算缓存、列表性能。

**参考答题**：模板函数可能在每次组件更新时对所有行重新执行。对稳定的派生数据可在数据适配层预处理、按 ID 缓存，或用 `computed` 生成视图模型；必要时把一行拆成具有稳定 props 的子组件。先用性能工具确认瓶颈，而不是无条件缓存。

**追问**：1000 行表格每行格式化时间字符串，何时该在后端、适配层或组件里处理？

### 10. [P1] `shallowRef` 与 `markRaw` 在图表或大数据场景怎么用？

**核心知识点**：浅层响应式、外部实例、引用替换。

**参考答题**：`shallowRef` 只追踪 `.value` 的替换，不递归转换内部对象，适合大块不可变数据；修改内部数组后需整体赋新引用才触发依赖。第三方图表实例通常不需要变为响应式对象，可保持普通局部变量，必要时使用 `markRaw`。两者是针对具体开销的工具，不能代替数据更新策略。

**追问**：实时曲线数组原地 `push` 后视图为何没有更新？

## B. 组件设计与生命周期（11–19）

### 11. [P0] 父子组件如何通信，何时使用 `v-model`？

**核心知识点**：单向数据流、props/emits、受控值。

**参考答题**：父组件通过 props 下发值，子组件通过 emit 通知变化。站点选择器这类“值由父组件持有”的控件适合使用 `v-model`，本质是值属性与更新事件的约定；子组件不应直接修改只读 prop。Vue 新版可以用 `defineModel()` 简化声明，但仍要明确空值和更新时机。

**追问**：用户在选择器里搜索输入但还没确认选择，搜索文本应该同步给父组件吗？

### 12. [P0] 插槽与 props 各适合扩展什么？

**核心知识点**：数据配置、内容组合、作用域插槽。

**参考答题**：固定、可描述的数据选项适合 props；调用方需要提供复杂界面内容时用插槽。业务表格可用列配置描述常规列，用作用域插槽定制状态、操作列；不要把所有差异都做成数十个布尔 props。插槽提供的数据契约要稳定且有类型。

**追问**：设备状态列既要颜色标记又要 tooltip，你如何避免在每页复制模板？

### 13. [P1] `provide/inject` 和 Pinia 的区别？

**核心知识点**：组件树范围、全局共享、依赖可见性。

**参考答题**：`provide/inject` 在祖先与后代之间传递上下文，适合表单、主题或某个看板局部配置；Pinia 适合跨路由、跨组件树的共享业务状态。二者都可能让依赖不如 props 显式，应在可维护性和共享范围之间选择。

**追问**：页面有两个独立站点面板，每个面板下方的组件需要自己的站点 ID，应该用全局 store 吗？

### 14. [P0] 组件卸载时需要清理哪些东西？

**核心知识点**：定时器、事件监听、请求、图表、订阅。

**参考答题**：由组件创建并独占的资源应在卸载时释放，例如 `setInterval`、`ResizeObserver`、DOM 监听、ECharts 实例和 WebSocket 订阅。请求可取消或至少忽略过期结果。若连接是多个页面共享的服务，组件只取消自己的订阅，不能直接关闭其他页面仍在使用的连接。

**追问**：切换路由后，为什么连接数持续增加？你会从哪里检查？

### 15. [P1] 什么时候把逻辑提取为 composable，而不是组件或 Pinia store？

**核心知识点**：复用逻辑与 UI 分离、状态生命周期。

**参考答题**：composable 复用状态和副作用逻辑，例如分页查询、连接状态、窗口尺寸监听；组件复用稳定的 UI 语义；store 保存需要跨组件或页面共享的状态。写 `useDeviceList()` 时要明确是否每次调用产生独立状态，以及是否需暴露 `stop()` 清理。

**追问**：两个页面各调用一次 `useWebSocket()`，到底是一条连接还是两条？

### 16. [P1] `Teleport` 解决什么问题？弹窗仍可能遇到什么问题？

**核心知识点**：DOM 放置位置、逻辑组件树、焦点与层级。

**参考答题**：`Teleport` 将弹窗等内容渲染到指定 DOM 容器，方便避开父容器裁剪和层级影响；逻辑上仍属于原组件树。它不会自动解决焦点管理、滚动锁定、键盘关闭和多弹窗层级，优先利用成熟组件库并验证这些行为。

**追问**：大屏容器设置了 `transform`，弹窗定位或层级不对，如何排查？

### 17. [P1] `defineExpose` 何时合理，何时应改用 props/emits？

**核心知识点**：组件公开接口、命令式调用、耦合。

**参考答题**：子组件用 `<script setup>` 时默认不向父组件暴露内部成员；需要父组件命令式执行 `focus()` 或 `open()` 时可以用 `defineExpose` 暴露最小方法。一般数据传递和状态变化仍用 props/emits，更容易追踪；大量调用子组件内部方法说明组件边界可能不清。

**追问**：父组件需要重置一个复杂查询表单，命令式 `reset()` 与受控值更新怎样选择？

### 18. [P0] 组件异步加载的 loading、error、empty 应如何区分？

**核心知识点**：状态建模、用户反馈、重试。

**参考答题**：首次加载期间不应显示“没有数据”；请求成功但空列表才是 empty；网络或服务失败应保留查询条件并给重试入口。刷新已有数据时可以继续展示旧数据并标明刷新中；实时连接中断时还需显示数据可能过期，不能误报为无设备。

**追问**：图表接口失败但其他指标成功，整个页面应变成错误页吗？

### 19. [P1] 组件库升级时最容易出现哪些回归？

**核心知识点**：组件 API、样式、事件、封装层。

**参考答题**：检查属性和事件是否变更、表单校验时机、表格选择行为、样式变量及覆盖规则。先查看迁移说明，更新封装层，再回归关键页面和异常状态；只确认页面能编译通过还不够。版本锁定与灰度验证有助于控制风险。

**追问**：升级后某个表单的校验提示不显示，如何缩小排查范围？

## C. Pinia 与状态边界（20–25）

### 20. [P0] 哪些状态应放进 Pinia？

**核心知识点**：共享范围、状态所有权、生命周期。

**参考答题**：当前用户、权限、跨页面共享的站点选择适合 store；单页弹窗开关、临时输入通常留在页面。判断依据是“谁读写、持续多久、页面切换后是否要保留”，而不是“状态重要不重要”。把全部实时点存进单一 store 还可能造成更新和清理问题。

**追问**：设备列表的筛选条件需要分享给同事，放 Pinia 还是 URL query 更合适？

### 21. [P0] 从 Pinia store 解构 state 后为什么可能失去响应式？

**核心知识点**：代理属性读取、`storeToRefs`。

**参考答题**：`const { user } = store` 读取的是当下的属性值，普通变量不会随 store 变化更新。解构 state/getter 时用 `storeToRefs(store)`；action 是方法，可以直接解构。若不需要解构，始终写 `store.user` 也清晰。

**追问**：从 store 解构 action 是否也必须用 `storeToRefs`？

### 22. [P1] Setup Store 与 Option Store 怎么选择？

**核心知识点**：写法差异、响应式能力、团队一致性。

**参考答题**：Option Store 用 `state/getters/actions` 对象组织，结构直观；Setup Store 用组合式函数写法，可自然使用 `ref`、`computed` 和 composable。两者都能满足常见后台需求；团队一致性、SSR/插件需求以及副作用可维护性比“哪种更先进”重要。

**追问**：在 Setup Store 内创建定时器或 socket，应在哪些场景清理？

### 23. [P1] 异步 action 失败后，该由 store 还是页面提示错误？

**核心知识点**：错误职责、复用、重复提示。

**参考答题**：action 应有明确的失败契约：抛出结构化错误或返回可辨识结果。页面根据操作场景决定提示、字段定位或重试；全局层可处理登录失效等统一问题。若 store 与页面都弹提示，用户会看到重复错误，且难以统一处理。

**追问**：两个页面调用同一个 `fetchUser()`，一个需要静默失败，一个需要显式重试，怎么设计？

### 24. [P0] 退出登录时需要清理哪些前端状态？

**核心知识点**：会话、权限、缓存、订阅、动态路由。

**参考答题**：清理用户与权限 store、用户专属业务缓存、已注册动态路由和实时订阅；再跳转登录页。还应由后端使会话失效，前端清理只是客户端状态管理。多标签页要考虑其他标签同步退出，避免旧数据继续展示。

**追问**：切换账号后设备列表仍显示上一个用户的数据，根因可能是什么？

### 25. [P1] 为什么在路由模块顶层调用 `useAuthStore()` 可能出问题？

**核心知识点**：Pinia 实例安装时机、组件外使用 store。

**参考答题**：组件外调用 store 时要确保 Pinia 实例已经可用；路由模块在应用安装 Pinia 前就可能执行顶层代码。可把调用放到导航守卫函数内，或显式传入 Pinia 实例。SSR 场景尤其要避免把多个请求的用户状态共享到同一全局实例。

**追问**：守卫在应用启动时触发，怎样验证它拿到的是正确的 Pinia 实例？

## D. Vite、路由与权限（26–34）

### 26. [P0] Vite 开发阶段快，与生产包小是同一回事吗？

**核心知识点**：开发服务、按需转换、生产构建。

**参考答题**：开发时 Vite 以原生模块和按需转换提升启动与热更新体验；生产构建仍要进行打包与优化。开发启动快不代表首屏资源一定小，生产性能要看实际构建产物、请求瀑布和目标设备。需要分别度量 HMR 与上线后的加载指标。

**追问**：开发模式一切流畅，生产首次打开很慢，你先查什么？

### 27. [P0] `import.meta.env.VITE_*` 可以存放密钥吗？

**核心知识点**：客户端构建产物、公开配置。

**参考答题**：不能。以 `VITE_` 前缀暴露的值会进入客户端代码，用户可以查看构建产物；它适合公开的 API 地址或开关。服务器密钥、数据库密码和长期凭证应由后端或服务端部署环境保存。

**追问**：同一份前端构建产物要部署到测试和生产环境，如何做运行时配置？

### 28. [P1] 路由懒加载一定能提升体验吗？

**核心知识点**：动态 import、首屏与后续访问取舍。

**参考答题**：懒加载可减少首屏加载未访问页面的代码，但第一次进入该页面需要另行下载资源。按页面和依赖大小拆分，结合用户访问路径、缓存和构建分析验证；把所有小组件拆成 chunk 可能带来大量请求与复杂度。监控大屏的 ECharts 模块常适合路由级拆分。

**追问**：用户经常从设备列表进入详情，详情是否仍要懒加载？

### 29. [P0] Vue Router 的 meta 与导航守卫各负责什么？

**核心知识点**：路由声明、统一访问检查、返回重定向。

**参考答题**：meta 声明路由的业务信息，例如是否要求登录、权限标识或页面标题；守卫读取这些信息并决定放行或重定向。守卫应等待必要的用户状态恢复，区分未登录、无权限和不存在的路由。若守卫中不断返回同一路径，可能形成重定向循环。

**追问**：权限接口还没返回时，为何不能立即把用户送到 403？

### 30. [P1] 动态注册路由后，为什么当前地址有时仍显示旧页面？

**核心知识点**：`addRoute` 只注册匹配规则、导航重新解析。

**参考答题**：`router.addRoute()` 不会自动重新执行当前地址的匹配；如果新路由恰好匹配当前 URL，可在合适时机用 `router.replace(current.fullPath)`，或在守卫里返回目标地址触发重新导航。要保证“已注册”状态确实变化，否则守卫可能无限重定向。

**追问**：登出时如何移除旧用户的动态路由，防止下一个账号继承？

### 31. [P0] 菜单权限、按钮权限与接口权限有什么关系？

**核心知识点**：用户体验与服务端鉴权、统一权限标识。

**参考答题**：前端根据权限标识过滤菜单、保护路由、控制按钮，是为了呈现正确入口；接口仍必须在服务端校验用户和资源权限。比如运维人员能进入告警页，不代表能确认所有站点的告警；数据范围由服务端保证。不要把前端权限判断当作安全边界。

**追问**：直接复制一个设备详情 URL，可以绕过菜单权限吗？服务端应返回什么？

### 32. [P1] 动态菜单与动态路由一定要完全由后端返回组件路径吗？

**核心知识点**：配置和代码边界、组件映射、安全性。

**参考答题**：后端可返回菜单及权限标识，前端用受控的组件映射表关联到本地页面；不要把服务端字符串当作任意模块路径直接执行。静态路由加守卫对中小系统也可行，动态注册适合模块权限差异大或插件化场景。选择依据是复杂度和维护需求。

**追问**：后端返回一个前端不存在的菜单标识，页面应如何处理？

### 33. [P0] 刷新 `/devices/123` 后登录态丢失，怎样恢复？

**核心知识点**：异步会话恢复、守卫等待、深层路由部署。

**参考答题**：应用启动时先恢复会话与权限，守卫等待结果再判断能否进入详情路由；恢复失败则进入登录。服务器还要支持 SPA 深层路由回退，否则浏览器直接请求 `/devices/123` 可能在前端代码运行前就返回 404。两种 404 要分开排查。

**追问**：会话尚未确认时，页面应显示什么，才能避免先闪现敏感内容？

### 34. [P1] 路由 `params` 与 `query` 如何用于设备后台？

**核心知识点**：资源身份、可分享筛选状态、参数变化复用组件。

**参考答题**：设备 ID 这类资源身份放 `params`，如 `/devices/123`；筛选词、页码、排序可放 `query`，便于刷新与分享。路由从一个设备 ID 切到另一个 ID 时，组件实例可能复用，要监听参数变化重新请求；对 query 做类型解析和默认值处理。

**追问**：`page=abc` 或 `page=-1` 出现在 URL 中时如何处理？

## E. UI 组件库、表单、表格与联调（35–42）

### 35. [P0] Element Plus / Ant Design Vue 的二次封装应封什么？

**核心知识点**：稳定业务语义、组件 API、避免过度封装。

**参考答题**：先封装跨页面重复且含业务规则的部分，如站点选择器、设备状态标签、统一查询区；保持 props、事件、插槽和类型清楚。若只是把原组件所有 props 原样转发，价值很小；若做成配置项繁多的万能表格，后续需求变化也难维护。用至少两个页面验证抽象是否稳定。

**追问**：两个设备页只有一列不同，要抽成一个大表格组件吗？

### 36. [P0] 表单校验只写在前端可以吗？

**核心知识点**：即时反馈与服务端权威校验、字段错误。

**参考答题**：前端校验用于及时提示必填、格式和范围；服务端仍需验证，因为请求可绕过界面，且业务约束可能变化。提交后要能把服务端字段错误映射回控件，并保留用户输入；未知错误则给可重试提示。单位、时区和空值约定也应纳入校验。

**追问**：功率输入 `0` 是合法值，为什么不能用 `if (!value)` 判断是否缺失？

### 37. [P1] 动态表单字段之间有依赖，怎样避免校验状态混乱？

**核心知识点**：条件字段、清理旧值、动态规则。

**参考答题**：先明确字段何时出现、隐藏后是否保留值、是否仍参与提交和校验。切换设备类型时，按业务规则清理不再适用的字段及其错误，动态更新校验规则，并在提交时以当前类型再校验一次。不能只靠 `v-if` 隐藏控件，却继续把过期字段发送给后端。

**追问**：编辑表单从设备 A 切到设备 B，旧校验错误为什么还显示？

### 38. [P0] 大表格的筛选、排序、分页应由谁管理？

**核心知识点**：统一查询模型、服务端分页、状态归一。

**参考答题**：页面维护一个明确的查询模型，再映射成接口参数；筛选或排序改变时通常重置页码，避免落到不存在的页。服务端分页可以控制网络和内存成本；表格组件负责展示与交互事件，不应自己偷偷保存另一份查询真相。空、加载、失败状态应可辨。

**追问**：编辑删除当前页最后一条后，页码超出总页数，怎么处理？

### 39. [P1] 多选表格跨页选择如何设计？

**核心知识点**：稳定 ID、已选集合、服务端范围。

**参考答题**：以设备 ID 而非行下标保存选择集合，明确“只选本页”还是“跨页保留”。若要“选择全部符合筛选条件”，不能在前端假装已拿到所有设备；应让后端根据筛选条件执行批量操作或返回选择令牌，并提示操作范围。刷新后哪些选择保留，要与产品确认。

**追问**：用户筛选后点击“全选”，再修改筛选条件，之前选择如何处理？

### 40. [P0] 表格快速切换筛选时，除了取消旧请求还要注意什么？

**核心知识点**：请求身份、加载状态、URL 同步。

**参考答题**：旧请求即使被取消，仍可能进入 `catch/finally`；只有当前请求才能更新列表、错误和 loading。输入框查询可防抖或点击提交，避免逐字请求；若筛选状态同步 URL，要避免 URL 与本地状态相互监听导致重复请求。服务端返回数据仍要按当前查询条件校验基本一致性。

**追问**：请求 A 慢、B 快；A 的 `finally` 最后执行，会造成什么界面问题？

### 41. [P1] 接口返回字段类型与 TypeScript 声明不一致，为什么编译仍通过？

**核心知识点**：编译期类型、运行时 JSON、边界校验。

**参考答题**：TypeScript 类型在运行时不验证网络响应；`response.json() as Device` 只是断言，不保证字段真的存在。对关键字段应在 API 边界进行运行时校验或明确的 DTO 映射，并把问题反馈给后端修复契约。不要在每个组件用零散的可选链掩盖异常。

**追问**：设备功率接口偶发返回字符串 `"18.4"`，你会在哪里处理？

### 42. [P0] 401、403、业务错误和网络错误应怎样区分？

**核心知识点**：身份失效、权限不足、可重试性、用户反馈。

**参考答题**：401 通常表示尚未认证或会话失效，应进入统一会话处理；403 表示已识别用户但无访问权限，展示无权限状态。业务错误按错误码提示字段或操作约束；网络失败可保留页面和输入并提供重试。写操作不能因网络错误就无条件自动重试，还要考虑是否已经在服务端成功。

**追问**：用户点“确认告警”后网络超时，如何避免重复确认或误以为失败？

## 使用这卷题库的方法

1. 第一轮只练 P0，每题用 **定义 → 原理 → 场景 → 边界** 讲 60–90 秒。
2. 第二轮练 P1，并把答案替换成自己项目中的真实例子；没有生产经验就明确说练习项目。
3. 遇到“怎么设计”的题，先说明假设和接口契约，再给方案、取舍与验证方式。
4. 重点复练第 4、14、24、31、38、40、42 题：这些最容易暴露实际项目经验。
