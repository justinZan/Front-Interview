# 04｜测试、部署、架构与项目追问题库

> 本卷聚焦联调、测试、构建部署、文档和跨团队协作。**P0** 为岗位核心题，**P1** 为延伸题。

## 知识点清单

- [ ] API 契约、DTO 与视图模型、单位/时间/空值约定。
- [ ] 请求竞态、错误分层、重试与幂等、接口版本兼容。
- [ ] 单元/组件/端到端测试的选择、mock 与真实集成的边界。
- [ ] Vite 构建、静态资源缓存、SPA 路由回退、发布与回滚。
- [ ] 线上错误定位、source map、日志上下文、可观测性。
- [ ] 监控平台的数据流、权限边界、实时与历史数据关系。
- [ ] 项目表达：职责、证据、取舍、结果、复盘。

## A. 架构与接口设计（1–10）

### 01. [P0] 一个监控后台的前端模块应该怎样划分？

- **知识点**：业务域、依赖方向、页面/组件/store/API 的边界。
- **答题要点**：按设备、站点、告警等业务域组织页面和服务。API 层处理网络与数据转换，页面组合交互，组件承担稳定 UI，Pinia 保存跨页面共享状态。先形成清楚边界，再依据真实复用抽取公共模块。
- **追问**：一个“万能表格组件”配置项超过 40 个时如何调整？

### 02. [P0] 前端和后端如何对齐设备列表接口？

- **知识点**：分页、筛选、排序、错误码、单位、时间、空值。
- **答题要点**：把请求参数、响应样例和异常样例写成契约，尤其确认页码从 0 还是 1 开始、`total` 含义、时间时区、功率单位及 `null` 语义。先用 mock 跑通正常与异常路径，联调后以真实响应复核契约。
- **追问**：接口返回 200 但业务码表示失败，统一请求层怎么处理？

### 03. [P0] DTO 与页面展示模型为什么可以分开？

- **知识点**：防腐层、类型、格式化、后端契约变化。
- **答题要点**：接口 DTO 表达传输数据，页面模型表达 UI 使用的数据。集中转换状态码、单位和时间，避免每个组件重复判断，也减少接口字段变更时的修改范围。转换层应保留原始值含义，不把 `null` 偷换成 0。
- **追问**：实时推送与 HTTP 快照的字段不一致时，转换放在哪里？

### 04. [P0] 请求失败后，哪些请求可以自动重试？

- **知识点**：幂等、安全重试、退避、用户反馈。
- **答题要点**：读取类请求或明确幂等的操作，才考虑在网络暂时失败时有限次重试，并配退避。写操作若没有幂等键或服务端去重机制，直接重试可能造成重复提交。应区分 401、403、校验错误和临时 5xx，不对所有错误一概重试。
- **追问**：确认告警接口超时了，但服务端可能已成功，下一步怎么做？

### 05. [P0] 如何防止快速切换筛选条件时旧结果覆盖新结果？

- **知识点**：请求竞态、取消、序号、状态一致性。
- **答题要点**：每次查询建立新的请求标识，取消旧请求或在结果返回时比较标识，只应用当前查询的结果。加载和错误状态也应属于当前请求，不能由旧请求的 `finally` 提前清掉。筛选变更时通常重置页码。
- **追问**：请求库不支持 `AbortController` 时怎么办？

### 06. [P1] 如何设计统一错误处理而不吞掉业务上下文？

- **知识点**：传输错误、业务错误、展示责任。
- **答题要点**：请求层统一识别网络失败、HTTP 状态和规范化错误对象；页面决定是字段提示、重试按钮、全局通知还是保留旧数据。统一层可以处理登录失效等跨页规则，但不应把所有错误都变成同一个 toast。
- **追问**：同一接口在大屏和编辑弹窗出错，提示方式应相同吗？

### 07. [P1] 怎样设计前端缓存以避免设备状态过期？

- **知识点**：缓存时效、主动失效、实时订阅、权威数据。
- **答题要点**：区分变化慢的站点/设备资料与变化快的实时测点。资料可带时效缓存并在编辑后失效；实时状态以快照和增量更新，并显示最后更新时间。缓存键必须包含站点、筛选和用户数据范围等影响结果的条件。
- **追问**：切换账号后，旧账号的缓存如何处理？

### 08. [P1] 时间和单位错误为什么在能源业务中特别危险？

- **知识点**：UTC、时区、秒/毫秒、W/kW、精度、空值。
- **答题要点**：曲线错位或功率扩大 1000 倍会直接误导运维判断。与后端约定存储/传输单位和时间格式，转换集中在边界层，UI 显示单位与时区；为 `0`、`null` 和缺测分别定义含义。
- **追问**：夏令时切换日的“按日能耗”如何展示？

### 09. [P1] 如何处理接口字段变更而不影响所有页面？

- **知识点**：契约版本、兼容期、适配层、回归。
- **答题要点**：先确认是后端误改还是正式版本变更；在 API 适配层统一转换，并明确兼容期限。用关键样例和页面回归确认新旧数据均可处理，最终删除临时兼容代码。
- **追问**：后端将 `power` 从 W 改为 kW，但字段名没变，如何防止静默错误？

### 10. [P1] 前端如何决定哪些状态放 Pinia，哪些状态放 URL？

- **知识点**：状态拥有者、分享/刷新、跨页面共享。
- **答题要点**：用户与权限等跨页面状态放 store；可分享、可回退的筛选条件可放 URL；仅当前组件使用的弹窗开关留在组件。避免同一个状态在多处各自维护而发生同步问题。
- **追问**：设备列表筛选条件需要用户复制链接分享时怎么做？

## B. 测试与质量保障（11–18）

### 11. [P0] 单元、组件、端到端测试分别测什么？

- **知识点**：测试层次、稳定性与成本。
- **答题要点**：单位换算、权限判断、事件去重适合单元测试；表单校验和空/错误状态适合组件测试；登录到处理告警这样的关键路径适合端到端测试。优先测业务规则与高风险流程，不把框架本身的行为重复测一遍。
- **追问**：图表可视化应该只做快照测试吗？

### 12. [P0] 如何测试 WebSocket 断线恢复？

- **知识点**：可控 mock、状态机、去重、补拉。
- **答题要点**：用可控制的 mock 服务依次发正常、重复、乱序、断线和恢复事件；断言连接状态、最后更新时间、设备状态及告警数量。断线后确认补拉事件被应用且不会重复插入。单元层可测事件归并，端到端层覆盖用户可见结果。
- **追问**：如何让测试不依赖定时器的真实等待？

### 13. [P0] 如何验证角色权限没有“漏口”？

- **知识点**：菜单、路由、按钮、API 的分层授权。
- **答题要点**：分别验证菜单入口、直接输入 URL、页面内按钮，以及直接调用后端接口。前端控制改善体验，服务端接口负责真正授权和数据范围。至少覆盖管理员、运维、只读三个角色与未登录状态。
- **追问**：同角色在不同站点的数据范围不同，测试矩阵怎么建？

### 14. [P1] 测试 mock 太理想化会造成什么问题？

- **知识点**：契约偏差、异常样例、真实集成。
- **答题要点**：如果只返回完整且稳定的数据，无法发现缺失字段、慢响应、状态码和时间单位问题。mock 应来自约定契约和真实样例，覆盖空值、错误、乱序与延迟；仍需真实接口联调确认。
- **追问**：mock 和真实接口不一致时，以谁为准、如何推进修正？

### 15. [P1] 如何测试图表在侧栏收缩、Tab 切换时不空白？

- **知识点**：图表实例、尺寸观测、可见性。
- **答题要点**：在容器尺寸变化、隐藏后显示、窗口缩放场景中观察图表容器尺寸与实例更新。检查 `resize()` 在有效尺寸下调用，组件卸载后实例已释放。功能测试可断言数据和交互，视觉问题结合截图或真实屏幕检查。
- **追问**：容器初始化时宽高都是 0，应该何时 `echarts.init`？

### 16. [P1] 什么情况下应该增加回归测试？

- **知识点**：缺陷复现、风险、可重复性。
- **答题要点**：出现过且可能复发的业务规则错误，先保留最小复现，再用适当层次的测试锁住行为。高风险改动（权限、告警状态、单位换算、实时数据）优先覆盖；纯样式微调可用人工或截图检查。
- **追问**：修复线上错位问题，测试应测 CSS 细节还是用户可见布局？

### 17. [P1] 如何检查一个页面有没有内存泄漏？

- **知识点**：资源生命周期、内存快照、重复进入/退出。
- **答题要点**：多次进入/离开页面，观察监听器、定时器、socket、图表实例和堆内存是否持续增长。通过 Performance/Memory 面板定位保留对象，检查是否由长寿命回调或全局容器持有。修复后用同一场景再测。
- **追问**：`onUnmounted` 已执行，为什么内存还可能不降？

### 18. [P1] 如何为“加载、空、错误、离线”设计验收条件？

- **知识点**：状态覆盖、用户下一步、产品验收。
- **答题要点**：写清每种状态的触发条件、可见文案和用户可进行的动作。例如离线时保留历史数据但标注“最后更新时间”，错误时提供重试；空结果区分无设备和筛选无匹配。验收不只看正常数据截图。
- **追问**：实时数据断开但 HTTP 接口仍可用时，页面应显示什么？

## C. 构建、部署与线上排查（19–27）

### 19. [P0] Vite 项目在生产环境刷新深层路由返回 404，原因是什么？

- **知识点**：SPA History 路由、服务器回退。
- **答题要点**：直接访问 `/devices/1` 时，浏览器向服务器请求该路径；若服务器只按静态文件找，就会返回 404。配置服务器把非 API、非静态资源的页面请求回退到 `index.html`，并检查部署子路径与 Vite `base`。
- **追问**：为什么开发环境没问题，生产才出现？

### 20. [P0] 发布后部分旧页面白屏，刷新又恢复，可能是什么？

- **知识点**：哈希资源、HTML 缓存、动态 import、原子发布。
- **答题要点**：先看控制台与网络请求；旧 HTML 可能引用部署后已删除的旧 chunk。保留一段时间旧资源，控制 HTML 缓存或采用原子发布；同时记录版本并给动态加载失败提供可恢复提示。
- **追问**：为什么简单地把所有静态资源都设为不缓存不合适？

### 21. [P0] 前端环境变量能放密钥吗？

- **知识点**：构建时替换、客户端可见、服务端配置。
- **答题要点**：Vite 暴露到客户端的变量会写入构建产物，用户可以查看，不能放数据库密码、签名密钥或长期有效私有 token。公开的 API 地址和功能开关可以配置；秘密留在服务端或部署平台的服务端环境。
- **追问**：同一份构建产物想部署到多个环境，如何配置运行时地址？

### 22. [P0] 线上图表偶发空白，你会怎么定位？

- **知识点**：复现条件、容器尺寸、生命周期、数据格式。
- **答题要点**：先收集浏览器、页面路径、切换步骤和数据规模，检查容器是否为 0 尺寸、是否在隐藏容器上初始化、实例是否绑定已销毁 DOM、数据是否异常。用日志和最小复现定位，再补对应的回归场景。
- **追问**：只在打开侧栏后出现，最可能从哪里查？

### 23. [P1] 线上只有个别用户出现 JS 错误，该收集什么上下文？

- **知识点**：错误采集、版本、source map、隐私。
- **答题要点**：记录版本、路由、浏览器、设备、错误栈、关键操作和请求关联 ID；用安全管理的 source map 映射代码位置。过滤 token、个人资料和业务敏感内容，避免把同一错误海量重复上报。
- **追问**：如何区分新版本缺陷与用户缓存旧资源导致的问题？

### 24. [P1] 如何设计前端发布后的回滚与验证？

- **知识点**：构建产物、版本、健康检查、静态资源兼容。
- **答题要点**：发布前保存可回滚构建产物和配置，明确回滚步骤；发布后检查登录、主要路由、接口和实时连接。回滚也要考虑旧页面引用的资源仍可访问，不能只替换 `index.html` 就宣布完成。
- **追问**：接口同时升级，前端回滚可能遇到什么兼容问题？

### 25. [P1] Source map 应怎样使用？

- **知识点**：错误定位、发布对应关系、访问控制。
- **答题要点**：构建时生成与版本匹配的 source map，供可信的错误平台或内部排障使用；按安全策略决定是否公开部署。错误事件需要携带发布版本，才能定位到正确的源文件和行号。
- **追问**：线上日志只有压缩后的栈，如何对应到源码？

### 26. [P1] 怎样判断一个前端优化真的有效？

- **知识点**：可重复测量、基线、指标与副作用。
- **答题要点**：固定设备、浏览器、网络、数据量和缓存条件，记录优化前后同一场景的指标，最好多次测量。除了速度，还检查错误率、内存、包体积和交互完整性，避免一个指标改善而其他方面退化。
- **追问**：实验室指标改善但真实用户没有感知，可能为什么？

### 27. [P1] 页面一直开着的监控大屏，运维上需要关注哪些问题？

- **知识点**：长时运行、内存、重连、数据新鲜度。
- **答题要点**：限制图表时间窗口和消息队列，清理不再使用的资源；展示连接状态与最后更新时间，确保断线恢复和补拉。通过长时间运行场景观察内存、CPU、连接数和错误累积，而不仅检查开屏效果。
- **追问**：浏览器切到后台后计时器节流，恢复时如何处理？

## D. 项目设计与协作追问（28–36）

### 28. [P0] 请用 3 分钟介绍一个最能匹配本岗位的项目。

- **知识点**：业务目标、个人职责、关键难点、结果。
- **答题要点**：按背景 → 目标 → 自己负责的部分 → 一个具体方案 → 验证结果 → 复盘讲述。优先选择监控、后台、可视化或复杂数据页面；没有生产经验则明确说明练习项目及真实测量结果。
- **追问**：这个方案中哪部分是你亲自设计并实现的？

### 29. [P0] 面试官说“这个功能其实组件库就有”，你如何说明自己的工作？

- **知识点**：业务建模、工程集成、非功能要求。
- **答题要点**：组件库提供基础控件，自己的工作在于接口契约、状态流、权限、异常处理、性能和维护边界。举一个具体页面说明如何把标准控件接入业务，并处理库默认能力之外的问题。
- **追问**：你封装的组件为什么比直接使用库组件更合适？

### 30. [P0] 需求快上线时变更，怎样保证交付？

- **知识点**：范围、验收、风险沟通、回归。
- **答题要点**：与产品确认必须交付的行为和验收标准，评估改动范围与受影响页面，拆分可独立上线部分；及时说明影响和风险。关键流程与异常路径做有针对性的回归，并留下变更记录。
- **追问**：如果新需求会让原计划无法按时交付，你怎么表达？

### 31. [P0] 与后端对实时推送格式有分歧，如何推进？

- **知识点**：契约协作、样例、版本、恢复能力。
- **答题要点**：从页面需求反推必要字段，如设备 ID、事件 ID、序号、时间、单位、快照/补拉方式；用正常、重复、乱序、断线的样例对齐。记录双方认可的协议和变更流程，先用 mock 并行开发。
- **追问**：后端不愿提供补拉接口，前端能否完全保证不丢消息？

### 32. [P1] 你如何处理一次自己引入的线上问题？

- **知识点**：止损、事实、根因、复盘。
- **答题要点**：先说明影响范围与止损动作，再讲定位证据、修复和验证；最后说明预防措施。讲清自己的责任和团队协作，避免只说“修好了”或把问题归因于别人。
- **追问**：如果暂时无法复现，怎样收集下次出现时的证据？

### 33. [P1] 如何向非技术同事解释“实时数据可能过期”？

- **知识点**：业务语言、数据新鲜度、风险。
- **答题要点**：说明页面保留的是最后一次成功更新的数据，并展示时间；连接恢复前不能把它当成当前设备状态。用具体例子解释可能影响的业务动作，再约定刷新或等待恢复的流程。
- **追问**：哪些操作在数据过期时应该禁用或再次确认？

### 34. [P1] 对新能源/物联网业务不熟悉，如何快速上手？

- **知识点**：实体关系、状态流、现场术语、异常案例。
- **答题要点**：先确认站点、设备、测点、告警和用户角色的关系，画出数据从设备到页面的链路；与产品、后端和运维核对单位及状态含义。通过真实案例和异常样例校正理解，再设计页面。
- **追问**：SOC、功率、电量三个指标的含义不清时怎么处理？

### 35. [P1] 项目没有漂亮的性能数字，面试时怎样描述优化？

- **知识点**：诚实陈述、测量方案、可验证结果。
- **答题要点**：不要编造结果。说明发现问题的证据、采用的方案、验证条件和可观察变化；若当时没有留数据，承认限制，并解释现在会如何设置基线、复测和记录。
- **追问**：你会优先选哪个场景重测，为什么？

### 36. [P1] 如果让你从头负责这个前端项目，第一周做什么？

- **知识点**：需求澄清、架构边界、风险排序、最小闭环。
- **答题要点**：先梳理角色、核心页面、数据与实时协议、异常场景、部署约束；确定技术栈和模块边界。优先打通登录、设备列表和一个实时指标的最小闭环，用它验证接口与部署，再扩展图表和复杂页面。
- **追问**：如何避免第一周花太多时间搭脚手架和抽象组件？
